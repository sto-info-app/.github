# Contributing to STO Info App

Thank you for your interest in contributing to the STO Info App project.

This document outlines how contributions are expected to work and the standards used across the organisation.

---

## General approach

- Contributions should be made via pull requests.
- Small, focused changes are preferred over large, sweeping updates.
- Code, documentation, and tests are all valid forms of contribution.

If you are unsure about an approach, opening an issue or draft pull request is encouraged.

---

## Branching and pull requests

- Create a branch for your change.
- Open a pull request against the appropriate default branch.
- Do not push directly to protected branches.

All pull requests are reviewed before merging.

---

## Code quality and review

When submitting a pull request, contributors are expected to:

- Understand the code they are submitting.
- Ensure existing tests pass and add new tests where appropriate.
- Consider error handling, edge cases, and maintainability.
- Avoid introducing unnecessary dependencies or complexity.

Reviews focus on correctness, clarity, and long-term maintainability.

---

## Use of AI-assisted tools

AI-assisted tools (such as code generation or refactoring tools) may be used, provided that:

- All generated code is reviewed and understood by the contributor.
- The contributor takes responsibility for correctness and security.
- No secrets, credentials, or sensitive data are included in prompts.

AI tools are treated as assistants, not authoritative sources.

---

## Security and data considerations

Extra care should be taken when working on areas involving:

- Authentication or authorisation
- File uploads or data imports
- Rate limiting, IP handling, or proxy behaviour
- Data retention, audit logging, or deletion processes

If you are unsure whether a change may affect security or data handling, please call it out explicitly in the pull request.

---

## Behaviour and expectations

- Be respectful and constructive in discussions and reviews.
- Assume good intent.
- Feedback should focus on the work, not the individual.

This project aims to be welcoming, calm, and professional.

---

## Licensing and responsibility

By contributing, you confirm that you have the right to submit the work and that it does not knowingly include proprietary or restricted material.

Final responsibility for merged changes rests with the project maintainers.
